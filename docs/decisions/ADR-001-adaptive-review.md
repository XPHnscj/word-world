# ADR-001：固定艾宾浩斯计划与自适应复习队列并行

## Status

Accepted

## Date

2026-08-17

## Context

项目的 Day 1/2/4/7/15/30 表格承担固定的学习计划展示，不能因为一次复习表现而改变列顺序；但真实记忆强度会因“认识 / 模糊 / 忘记”、生成能力和跨场景迁移而变化。复习需要在本地长期运行、离线可用，并且不能依赖服务端数据库。

## Decision

保留固定计划表，同时为词卡增加 `masteryLevel`（Lv0 初见到 Lv4 融入）和可选迁移场景。到期词通过 `buildAdaptiveQueue` 按风险排序，最多取 30 张进入独立的复习队列。

- Lv1 识别：回到原始语境判断是否认识。
- Lv2 理解：只展示英文释义，用户选择认识程度后再揭示中文。
- Lv3 调用：用户写出包含目标词的完整句子，先本地初筛，再尝试 AI 评估。
- Lv4 融入：切换到不同话题场景，要求用户再次自然调用词汇。
- “忘记”会把词安排到次日，并在当前队列末尾再次出现；“模糊”缩短间隔；“认识”逐级延长间隔。

AI 不可用时保留本地句子检查和用户自评，保证本地应用仍可继续使用。学习卡片、短文、复习记录继续写入 IndexedDB，模型评估只通过 `/api/reviews/evaluate` 进行。

## Alternatives Considered

### 仅使用固定艾宾浩斯列

实现简单，但无法区分遗忘、模糊和已经能主动调用的词，复习量会长期失真。Rejected。

### 仅使用 AI 评分

自然度判断更强，但离线不可用、延迟和 API 配置会阻断学习。Rejected。

### 只保留单一“对 / 错”结果

无法表达模糊记忆，也无法承接生成和迁移阶段。Rejected。

## Consequences

- 固定计划表仍然稳定，用户可以看懂艾宾浩斯节点。
- 复习队列会随表现变化，风险较高的词优先出现。
- IndexedDB 中旧词卡没有 `masteryLevel` 时会按旧 `stage` 推导，兼容已有本地数据。
- 生成和迁移阶段会多一次评估请求，但 AI 失败不会让复习流程中断。
